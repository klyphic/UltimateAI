Quick start

Set your API key once, then send a chat completion. Replace YOUR_PROXY_API_KEY with the key issued for your UltimateAI deployment. Do not publish your key in frontend code or public repositories.

GET/v1/models
curl "https://ai.fastdevelopers.in/v1/models" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY"
POST/v1/chat/completions
curl -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: my-agent-001" \
  -d '{
    "model": "deepseek-chat",
    "messages": [
      {"role": "user", "content": "Hello! Introduce yourself briefly."}
    ],
    "stream": false
  }'
Use a stable, unique x-agent-session value for each independent agent or conversation. Reuse that same value on later turns to continue its conversation.

Authentication

Send the proxy key using either supported header format. The key is required for API endpoints except the public health, readiness and documentation pages.

# Preferred: Bearer token
-H "Authorization: Bearer YOUR_PROXY_API_KEY"

# Also supported
-H "x-api-key: YOUR_PROXY_API_KEY"
Keep the key on your backend. Never embed a production proxy key in browser JavaScript, Android APK assets, or a public website.

Models

Call GET /v1/models for the live list of aliases currently exposed by this deployment. Model availability can change with upstream DeepSeek Web behavior.

GET/v1/model-capabilities
curl "https://ai.fastdevelopers.in/v1/model-capabilities" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY"

Chat Completions

Endpoint: POST /v1/chat/completions. Accepts standard chat messages, system instructions, optional tools and stream.

Multi-turn conversation

Send the same session header for every turn. This example asks a second question using the same agent session.

# Turn 1
curl -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: support-agent-42" \
  -d '{
    "model": "deepseek-chat",
    "messages": [
      {"role": "user", "content": "Remember this: my project is called Klyphic. Reply OK."}
    ],
    "stream": false
  }'

# Turn 2 — reuse exactly the same session ID
curl -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: support-agent-42" \
  -d '{
    "model": "deepseek-chat",
    "messages": [
      {"role": "user", "content": "What is the name of my project?"}
    ],
    "stream": false
  }'

Streaming responses

Set "stream": true and use curl -N to keep the Server-Sent Events stream visible as it arrives.

curl -N -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: streaming-agent-01" \
  -d '{
    "model": "deepseek-chat",
    "messages": [
      {"role": "user", "content": "Write a detailed explanation of how HTTP works."}
    ],
    "stream": true
  }'

Streaming responses use SSE data events and finish with data: [DONE]. If a stream has already started, a late upstream error is delivered as an SSE error event.

Sessions & conversation memory

Session identity is selected in this order:

  1. x-agent-session request header (recommended)
  2. session field in JSON body
  3. user field in JSON body
  4. Fallback to the request's remote IP (local loopback requests use dev-agent)
For stateful mode, provide a stable x-agent-session to keep each conversation isolated. Stateless mode does not need any session ID.

Stateless request (no session ID required)

Set session_mode to stateless in the JSON body, or send x-session-mode: stateless. The server generates a random internal session ID for that request, creates a fresh DeepSeek chat, returns the response, and then deletes the temporary remote chat. No x-agent-session, session, or user value is needed. Send the complete conversation messages in each stateless request because no conversation history is retained.

curl -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \\
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \\
  -H "Content-Type: application/json" \\
  -d '{
    "model": "deepseek-chat",
    "session_mode": "stateless",
    "messages": [
      {"role": "user", "content": "Hello!"}
    ],
    "stream": false
  }'

List active sessions

curl "https://ai.fastdevelopers.in/v1/sessions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY"

Reset one agent session

curl -X POST "https://ai.fastdevelopers.in/reset-session?agent=support-agent-42" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY"

Resetting one session starts a fresh remote DeepSeek chat while retaining local recovery history where available.

Reset all sessions

curl -X POST "https://ai.fastdevelopers.in/reset-session?agent=all" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY"
This is destructive: it clears all currently loaded sessions and all persisted session rows. Use only for maintenance/testing.

Start a new chat using the /new command

Send /new as the latest user message with the same session ID to reset that agent's chat and history.

curl -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: support-agent-42" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "/new"}],
    "stream": false
  }'

Anthropic Messages API

Endpoint: POST /v1/messages. The proxy accepts Anthropic-style system, messages, max_tokens, tools and stream fields.

curl -X POST "https://ai.fastdevelopers.in/v1/messages" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -H "x-agent-session: anthropic-agent-01" \
  -d '{
    "model": "deepseek-chat",
    "max_tokens": 1024,
    "system": "You are a concise technical assistant.",
    "messages": [
      {"role": "user", "content": "Explain REST APIs in simple terms."}
    ],
    "stream": false
  }'

OpenAI Responses API

Endpoint: POST /v1/responses. Send a string or structured input array. Use instructions for system-level guidance.

curl -X POST "https://ai.fastdevelopers.in/v1/responses" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: responses-agent-01" \
  -d '{
    "model": "deepseek-chat",
    "instructions": "You are a helpful coding assistant.",
    "input": "Show a Python function that checks whether a number is prime.",
    "stream": false
  }'

Image input

Image input is supported through inline base64 image data for PNG, JPEG, WebP and GIF. The deepseek-vision alias is listed when image upload is enabled on the server.

For privacy and SSRF safety, remote image URLs are not downloaded by this proxy. Send a data URL instead. Keep images within the deployment's configured size limits.

# IMAGE_BASE64 must contain the base64 bytes of a PNG/JPEG/WebP/GIF image.
curl -X POST "https://ai.fastdevelopers.in/v1/chat/completions" \
  -H "Authorization: Bearer YOUR_PROXY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-agent-session: vision-agent-01" \
  -d '{
    "model": "deepseek-vision",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "Describe this image."},
        {"type": "image_url", "image_url": {"url": "data:image/png;base64,IMAGE_BASE64"}}
      ]
    }],
    "stream": false
  }'

Errors & troubleshooting

HTTPMeaningWhat to do
400Invalid request or unsupported/unknown modelCheck JSON, required messages and model list.
401Missing or invalid proxy keyCheck Bearer token or x-api-key.
404Unknown endpoint or requested session not foundCheck path and agent ID.
413Request body exceeds 10 MBReduce payload/image size.
429Rate limited or upstream account pool unavailableHonor Retry-After and retry later.
502Upstream or malformed tool-call responseInspect error JSON and retry if appropriate.
503Proxy busy or no ready upstream accountRetry with backoff; check /readyz.
504Upstream request timeoutRetry after a short delay.
